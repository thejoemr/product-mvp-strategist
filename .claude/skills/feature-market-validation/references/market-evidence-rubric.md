# Ficha de evidencia de mercado por feature

| Campo | Descripción |
|---|---|
| Feature ID | ID del inventario, no un nombre ambiguo |
| Mercado objetivo | Segmento, industria, geografía y problema |
| Alternativa | Proveedor existente, proceso manual o solución de no-consumo |
| Fuente | Emisor/título, URL, fecha de consulta, fecha de publicación si conocida |
| Hecho verificable | Precio de plan, función listada, queja específica, contrato reportado; cita/paráfrasis limitada |
| Tipo | Oferta, precio, dolor, compra, uso, regulación, posicionamiento |
| Lectura comercial | Qué implica para comprador o versión mínima, marcada como inferencia |
| Limitación | Sesgo, falta de contexto, fuente patrocinada, segmento no equivalente |
| Fuerza | Fuerte, Media, Débil, Sin evidencia, Sin acceso web |
| Decisión sugerida | Acción candidata y pregunta de validación |

## Jerarquía práctica de señales

1. **Más directas**: compras/contratos y renovación para el segmento, investigaciones rigurosas con muestra/metodología, uso y churn (si el usuario las facilita).
2. **Indicadores útiles**: quejas con contexto en reviews originales, solicitudes recurrentes, entrevistas detalladas publicadas, comparativas basadas en pruebas.
3. **Indicadores indirectos**: feature disponible en un tier pagado, pricing oficial, documentación oficial de flujo. Muestra estrategia del vendedor más que willingness-to-pay del cliente.
4. **Señales débiles**: posts de marketing, SEO, listas genéricas, opinión aislada, términos de búsqueda sin comportamiento de compra.

## Guía de búsquedas: individualiza por segmento

- `[job to be done] [industry] manual process pain`.
- `[competitor] pricing [feature/limitation]` (verificar página oficial).
- `[competitor] [feature] reviews setup complexity limitations`.
- `[segment] willing to pay [outcome]` (no tratar resultados de blog como evidencia fuerte).
- `site:reddit.com [category] [pain]` para señales comunitarias, sin inferir mercado estadísticamente.

## Ritmo y cobertura

Para 50 features, prioriza 5–10 clusters y haz investigación profunda en las features que cambian el MVP o afectan pago. Mantén **una celda de resultado de mercado para cada feature**, incluidos obligatorios con valor comercial indirecto; cuando no exista fuente relevante, registra «no se encontró evidencia». No maquilles investigación incompleta como validación exhaustiva.
